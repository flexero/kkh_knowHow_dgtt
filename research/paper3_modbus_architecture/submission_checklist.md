## 4. Findings for the fmsctl software (not edits – for the author to decide)

- **Sequence guard (stale-frame hazard).** Fault case F8 shows that the V1.2 toggle-only PLC logic (as in the fmsctl
  virtual plant) executes the current job a second time if a stale REQ frame from an old TCP connection arrives after the
  next command (20 of 20 repetitions). Adding "accept a toggle only if cmd.seq ≠ hs.ackSeq" removed it (0 of 20).
  Recommended for map V1.3, the virtual plant and both PLC templates.
- **DeviceLink frames.** `DeviceLink.command()` uses 7 frames before the toggle and about 11 in total; with a 10 ms scan
  this takes 89 ms against 50 ms (20 ms poll) or 38 ms (5 ms poll) for the 3-frame sequence (Table 11). Optional
  optimisation; also reduces fault exposure.
- **Thesis metric.** The thesis bench reported "achieved rate" as 1/max(mean cycle, P), not the measured poll rate;
  the new bench measures the actual rate (it agreed within 0.4 % here). Consider correcting the thesis wording.
- **Gateway cost.** The thesis value t_gw = 0.04 ms is a conservative bound; the parallel gateway data imply 0.013 ms.
